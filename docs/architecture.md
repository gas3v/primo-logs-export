# Устройство расширения

## Поток выполнения

1. Пользователь кликает на иконку (`chrome.action.onClicked`, формат xlsx) или выбирает пункт
   контекстного меню иконки (`chrome.contextMenus.onClicked`, пункты `export-xlsx` / `export-csv`
   создаются в `runtime.onInstalled` с `contexts: ['action']`).
2. Разрешение `activeTab` даёт временный доступ к текущей вкладке (в том числе после клика по пункту меню).
   `chrome.scripting.executeScript` сначала записывает формат в `window.__primoExportFormat`
   (если выгрузка не идёт), затем внедряет `xlsx-writer.js`, `csv-writer.js` и `exporter.js`
   в изолированный мир контент-скрипта (ISOLATED world).
   Оттуда доступны DOM, `localStorage` и Performance API страницы, `fetch` к её API (тот же origin)
   и `chrome.runtime` для передачи файла в `background.js`.
3. `exporter.js`:
   1. Читает токен из `localStorage.token`.
   2. Берёт `operationKey` (GUID) из пути страницы.
   3. Строит параметры запроса из фильтров в адресе страницы.
   4. Загружает справочник типов событий.
   5. Постранично загружает события (по 1000 за запрос, `pageNumber` начинается с 0) до `filterCount`.
   6. Формирует строки, вызывает `window.__primoXlsx.build()` или `window.__primoCsv.build()`, создаёт
      blob-ссылку и отправляет её в `background.js` сообщением `{type: 'primo-download', url, filename}`.
4. `background.js` проверяет сообщение (blob-ссылка того же origin, что и вкладка-отправитель, имя `.xlsx`/`.csv`)
   и сохраняет файл через `chrome.downloads.download`. Если это не удалось, плашка становится оранжевой
   и показывает кнопку «Скачать файл»: клик по ней — жест пользователя, такое скачивание проходит.
5. Прогресс (с оценкой оставшегося времени) и ошибки показываются плашкой в правом нижнем углу страницы.
   Ошибку внедрения скрипта `background.js` показывает значком `ERR` и подсказкой у иконки.

### Почему не `<a download>`

До версии 1.0.1 файл скачивался программным кликом по `<a download>` со страницы. К моменту скачивания
(выгрузка 13 825 событий занимает около минуты) жеста пользователя уже нет, и Chrome разрешает странице
только одно такое скачивание. Следующее он задерживает с окном «Сайт пытается скачать несколько файлов»
или блокирует молча, если для сайта выбрано «Блокировать». Ограничение снимает только перезагрузка
страницы; переходы внутри SPA оркестратора его не сбрасывают. Скачивания через `chrome.downloads`
под это ограничение не попадают. Проверено 2026-11-11 на тестовом стенде (UI 4.26.7.13).

### Глобальные переменные

Живут в изолированном мире расширения на вкладке, скриптам страницы не видны:

| Переменная | Назначение |
|---|---|
| `__primoExportRunning` | идёт выгрузка; повторный запуск (клик или пункт меню) молча игнорируется |
| `__primoExportFormat` | `'xlsx'` / `'csv'`, записывает `background.js` перед внедрением; не меняется во время выгрузки |
| `__primoXlsx`, `__primoCsv` | генераторы, определяются один раз на страницу |

Blob-ссылка на готовый файл живёт 10 минут: её используют `chrome.downloads` (в том числе пока открыт
диалог «Сохранить как») и кнопки «Скачать ещё раз» / «Скачать файл» на плашке.

## Страницы

`operationKey` берётся из первого GUID в пути страницы:

- `/administration/robots/<robotId>/operation/<operationKey>/<robotName>/...`
- `/journal/orchestrator-robots/<operationKey>/operation/<robotName>?backUrl=…&filters=…`
  (раздел «Оркестраторные роботы», проверено на UI 4.26.7.13)

Если GUID в пути нет, используется GUID из последнего запроса страницы к `OperationEvents`.

## API Primo Orchestrator

Проверено на UI 4.26.7.x / WebApi 1.26.7.x.

### Авторизация

Cookie не используются. UI хранит в `localStorage.token` JSON-объект
`{token, fullName, tenantId, tenantName, rolePermissions, isAdmin, …}`. Каждый запрос отправляется
с заголовком `Authorization: Bearer <token>`.

### События операции

```
GET /api/robotlogs/OperationEvents/{operationKey}
    ?pageNumber=0            нумерация с 0
    &pageSize=1000           сервер принимает как минимум 10000
    &eventDate1=2026-11-03T12:07:46   локальное время браузера, без зоны
    &eventDate2=2026-11-10T12:07:46
    [&EntityId=…] [&ParsedElementName=…] [&ParsedElementId=…]
    [&ParsedElementClass=…] [&ParsedMessage=…] [&WithScreenFile=true]
```

Ответ:

```json
{
  "projectName": "DemoProject",
  "totalCount": 29,
  "filterCount": 29,
  "result": [
    {
      "id": "…", "eventDate": "2026-11-05T13:25:25.854134", "source": 0, "event": 4,
      "entityId": null, "userName": null, "projectId": 1, "projectName": "DemoProject",
      "robotId": 1, "robotName": "robot01", "robotKey": "…", "workerId": 1,
      "workerName": "agent01 (192.0.2.10)", "text": "05.11.2026 13:25.25.854 Debug: …",
      "parsedDateEvent": "…", "parsedType": 4, "parsedElementName": "Клик мышью",
      "parsedElementId": "…", "parsedElementClass": "LTools.Desktop.Elements.WFClick",
      "parsedMessage": "Осуществлен клик мышью на элементе …",
      "orchTimestampUtc": "…", "operationKey": "…", "signature": "…", "correctSignature": true,
      "eventType": null, "screenFilePath": null, "extDataJson": null
    }
  ]
}
```

- `source`: 0 означает робота, 1 означает оркестратор.
- Даты приходят без часового пояса. В Excel и CSV они записываются как есть, без пересчёта.
- Скорость (тестовый стенд, 2026-11-11): на страницу из 1000 событий ~1,6 с до первого байта
  и ~2–3 с на передачу ~1 МБ JSON. 13 825 событий — 14 запросов, ~58 с.
- В `parsedElementName` и `parsedElementId` робот добавляет U+200B, расширение его удаляет.

### Справочник типов событий

```
GET /api/robotlogs/OperationEventTypes/{operationKey}
→ [{ "event": 96, "source": 0, "names": ["ProjectCompleted", "Success"] }, …]
```

Ключ сопоставления: `source:event`. Названия склеиваются через «, », как в UI.

## Фильтры страницы

Параметр `filters` в адресе страницы содержит `btoa(encodeURIComponent(JSON.stringify(filters)))`, например:

```json
{ "eventDate": ["2026-11-03T09:07:46.622Z", "2026-11-10T09:07:46.622Z"], "withScreenFile": false }
```

Как UI переводит фильтры в параметры API (проверено подстановкой всех ключей):

| Ключ в `filters` | Параметр API |
|---|---|
| `eventDate[0]`, `eventDate[1]` (UTC ISO) | `eventDate1`, `eventDate2` (локальное время, `YYYY-MM-DDTHH:mm:ss`) |
| `entityId` | `EntityId` |
| `parsedElementName` | `ParsedElementName` |
| `parsedElementId` | `ParsedElementId` |
| `parsedElementClass` | `ParsedElementClass` |
| `parsedMessage` | `ParsedMessage` |
| `withScreenFile: true` | `WithScreenFile=true` |
| `source`, `event`, `text` | не передаются (поведение UI для них не проверено) |

Если параметра `filters` в адресе нет, расширение берёт параметры последнего запроса страницы
к `OperationEvents` из `performance.getEntriesByType('resource')`.

## Генератор csv (`csv-writer.js`)

- Разделитель `;`: в русской локали Excel запятая — десятичный разделитель, и файл с `,` не делится на колонки.
- UTF-8 с BOM (`\uFEFF` в начале): без BOM Excel читает файл как Windows-1251 и портит кириллицу.
- Строки через CRLF. Поле берётся в кавычки, если в нём есть `;`, `"`, CR или LF; кавычки удваиваются.
- Колонки с `type: 'date'` записываются как `дд.мм.гггг чч:мм:сс.000` (миллисекунды, без пересчёта зоны).
- Значения не экранируются от интерпретации как формул (`=`, `+`, `-`, `@`): данные сохраняются как есть.

## Генератор xlsx (`xlsx-writer.js`)

- ZIP с методом STORE (без сжатия), CRC32 по таблице, UTF-8 имена файлов (флаг 0x0800).
- Части: `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml`, `xl/_rels/workbook.xml.rels`,
  `xl/styles.xml`, `xl/worksheets/sheet1.xml`.
- Строки записываются как `inlineStr` (без sharedStrings). Числа и даты записываются как `<v>`.
- Стили: 0 обычный, 1 заголовок (жирный, сиреневая заливка), 2 дата (`numFmtId 164`
  `dd.mm.yyyy hh:mm:ss.000`).
- Дата Excel: `Date.UTC(…)/86400000 + 25569`, точность до миллисекунд (микросекунды отбрасываются).
- Закреплённая первая строка (`pane ySplit=1`), автофильтр и `_xlnm._FilterDatabase`.
- Из текста удаляются символы, недопустимые в XML 1.0. Длина ячейки ограничена 32 767 символами.

> **Важно:** в исходниках символы U+FFFE/U+FFFF допустимы только в виде escape-последовательностей
> `\uFFFE`, `\uFFFF`. Если они записаны буквально, Chrome отказывается загружать файл с ошибкой
> «isn't UTF-8 encoded». `scripts/pack.ps1` это проверяет.

## Проверка

Генераторы xlsx и csv покрыты тестами (`npm test`, папка `test/`): разметка, экранирование, даты, CRC32 и структура ZIP.
Остальное проверяется вручную.

Ручная проверка 2026-11-10 на тестовом стенде (UI 4.26.7.x):

- Небольшая операция: выгружено 29 событий, как в счётчике «Записей» в UI. Названия событий
  и колонки совпадают с таблицей.
- Генератор: 20 000 строк, спецсимволы `<>&"'`, управляющие символы, строка 40 000 символов.
  Файл открывается в openpyxl, даты распознаются с миллисекундами, автофильтр и закрепление на месте.

Ручная проверка 2026-11-11 на тестовом стенде (UI 4.26.7.13), крупная операция:

- Загружено 13 825 событий из 13 825 (счётчик «Записей» в UI), все запросы HTTP 200, ~58 с.
- Версия 1.0.0: второе скачивание подряд без F5 Chrome задержал окном «Сайт пытается скачать
  несколько файлов»; после F5 скачивание снова проходит. Воспроизведено тестовыми `<a download>`.
- Версия 1.0.1+: повторные выгрузки без F5 скачиваются; оставшееся время отображается;
  повторные клики во время выгрузки игнорируются.
- Версия 1.1.0: CSV через меню иконки открывается в Excel двойным щелчком, колонки и кириллица корректны.
  `csv-writer.js` проверен в Node: BOM, кавычки, `;` и перевод строки внутри поля, пустые значения.

Порядок ручной проверки после изменений:

1. Перезагрузить расширение в `chrome://extensions`, обновить страницу событий операции.
2. Левый клик → `.xlsx`; число строк совпадает со счётчиком «Записей».
3. Не обновляя страницу, правый клик → «Выгрузить в CSV» → файл скачивается, открывается в Excel.
4. Повторный клик во время выгрузки ничего не запускает.
